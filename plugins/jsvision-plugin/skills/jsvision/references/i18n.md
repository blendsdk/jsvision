# Internationalization

Use first-party `@jsvision/i18n` when an application needs non-English framework labels,
application-owned translatable copy, locale formatting, or runtime catalog sources. Keep the
isolated no-config English service when none of those apply.

## Decide the catalog boundary

- Ask for the target locale and fallbacks. Use explicit tags in generated applications.
- Import one requested locale from each framework package the application uses, such as
  `@jsvision/ui/locales/nl` or `@jsvision/code-editor/locales/nl`. Never import or synthesize an
  all-locales bundle.
- Define application keys under an application namespace. Put framework catalogs first and the
  application catalog last so application-owned overrides are deliberate.
- Create one `I18n` service and inject it into `createApplication({ i18n })`. Pass that same service
  to package helpers and `CodeEditor`/`CodeEditorWindow` instances that accept one; do not create a
  global registry or one service per component.
- Do not install dependencies from a generated recipe. Use the versions already declared by the
  consumer project and report missing packages.

Use the complete [localized application recipe](recipes/i18n-app.md) as the starting point.

## Author messages

```ts
import { defineCatalog, plural, select } from '@jsvision/i18n';

const appNl = defineCatalog({
  schema: 1,
  locale: 'nl',
  messages: {
    'app.greeting': 'Hallo ${name}',
    'app.file-count': plural('count', {
      one: '${count} bestand',
      other: '${count} bestanden',
    }),
    'app.account-state': select('state', {
      active: 'Actief',
      other: 'Onbekend',
    }),
  },
});
```

Plural categories come from cardinal `Intl.PluralRules` for the resolved message locale. Always
provide `other`; add `one`, `few`, `many`, and other categories only when the target locale uses
them. Select cases match exact strings and also require `other`. Pass controllers and interpolation
values through `t(key, { params })`; `$${name}` renders a literal `${name}`.

## Size translated actions from the rendered Buttons

Build every co-visible action first, then measure and compose the complete logical group. The shared
metric uses each Button's natural terminal-cell width, so accelerator markup is excluded and
wide/combining captions match the renderer.

```ts
import { Button, buttonGroup, measureButtonGroup } from '@jsvision/ui';

const actions = [new Button(i18n.t('app.action.save')), new Button(i18n.t('app.action.cancel'))];
const metrics = measureButtonGroup(actions, { minimumButtonWidth: 10, gap: 2 });
const actionBand = buttonGroup(actions, { minimumButtonWidth: 10, gap: 2 });
// Size the containing surface to at least metrics.width before adding actionBand.
```

Measure the complete group once, including buttons that a constrained component will place on a
second row. Use `maxColumns` for stable row-major wrapping or `buttonColumn` for a vertical action
rail. Do not size translated captions with JavaScript `.length`.

## Respect runtime boundaries

The main package entry is browser-safe. Import `@jsvision/i18n/node` only in Node composition code
that needs JSON file sources. For remote catalogs, use `loadI18n` with a caller-owned
`AbortSignal`; the application owns networking, authentication, timeout, retry, and caching.
Required source failure prevents publication, while optional source failure records a diagnostic.

```ts
import { loadI18n } from '@jsvision/i18n';
import { uiNl } from '@jsvision/ui/locales/nl';

const controller = new AbortController();
const signal = AbortSignal.any([controller.signal, AbortSignal.timeout(5_000)]);
const i18n = await loadI18n({
  locale: 'nl',
  catalogs: [uiNl],
  signal,
  sources: [
    {
      name: 'application-catalog',
      required: true,
      async load({ signal: sourceSignal }) {
        const response = await fetch('/locales/nl.json', { signal: sourceSignal });
        if (!response.ok) throw new Error('Catalog request failed');
        return response.json();
      },
    },
  ],
});
```

Use `setCatalog` for an atomic runtime overlay. An invalid replacement throws before publication,
so existing readers keep the previous catalog.

## Validate and verify

- Use partial validation for application overlays. Use strict validation with a reference catalog,
  placeholder manifest, and accelerator manifest for complete official catalogs.
- Preserve `~X~` accelerator markers, uniqueness among co-visible controls, and label width under
  every shipped locale.
- Render normal and constrained terminal sizes using the longest supported translations.
- Test plural categories, missing parameters, missing keys, diagnostics, and fallback order.
- Confirm main-entry browser bundles contain no non-English catalogs and Node-only imports.
- Run package typechecks/tests plus the consumer repository's normal full gate.
