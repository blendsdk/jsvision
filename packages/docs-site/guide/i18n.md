# Internationalization

JSVision applications can share one locale-bound service across framework controls and application
copy. English remains the default, so an existing no-config application keeps its current English
behavior.

## Install and choose an entry point

Install the engine alongside the packages whose catalogs you use:

```bash
npm install @jsvision/i18n @jsvision/ui @jsvision/forms @jsvision/files @jsvision/datagrid
```

The main `@jsvision/i18n` entry is browser-safe, ESM-only, and has no runtime dependencies. Node
catalog-file loading is deliberately separate:

```ts
import { createI18n, defineCatalog, loadI18n, plural, select } from '@jsvision/i18n';
import { jsonFileSource } from '@jsvision/i18n/node';
```

Import only the requested framework locale. There is no all-locales entry point:

```ts
import { uiNl } from '@jsvision/ui/locales/nl';
import { formsNl } from '@jsvision/forms/locales/nl';
import { filesNl } from '@jsvision/files/locales/nl';
import { datagridNl } from '@jsvision/datagrid/locales/nl';
```

## Define application messages

Catalog keys should be namespaced. Interpolation uses named parameters; `$${name}` escapes a
placeholder and renders the literal text `${name}`.

```ts
const appNl = defineCatalog({
  schema: 1,
  locale: 'nl',
  messages: {
    'app.greeting': 'Hallo ${name}',
    'app.files': plural('count', {
      one: '${count} bestand',
      other: '${count} bestanden',
    }),
    'app.account': select('status', {
      active: 'Actief',
      other: 'Onbekend',
    }),
    'app.placeholder-help': 'Schrijf $${name} voor een tijdelijke aanduiding.',
  },
});
```

`plural` uses cardinal `Intl.PluralRules` for the locale of the resolved message. Always provide
`other`; add categories such as `one`, `few`, or `many` when that locale uses them. `select` chooses
an exact string case and also requires `other`.

## Load the Application

Create one service, put framework catalogs first, put the application catalog last, and inject that
exact service into the application:

```ts
import { createApplication } from '@jsvision/ui';

const i18n = createI18n({
  locale: 'nl',
  catalogs: [uiNl, formsNl, filesNl, datagridNl, appNl],
});

const app = createApplication({
  i18n,
});
```

Later catalogs win for duplicate keys in the same locale. Keeping the application catalog last
therefore makes application-owned overrides explicit. The returned `app.i18n` is the same instance,
which can also be passed to Forms, Files, and Datagrid helpers that accept an i18n service.

Translate and format through that service:

```ts
i18n.t('app.greeting', { params: { name: 'Ada' } });
i18n.t('app.files', { params: { count: 2 } });
i18n.number(12345.67);
i18n.date(new Date('2026-07-25T12:00:00Z'));
i18n.compare('appel', 'peer');
```

Missing keys, parameters, and controllers produce bounded, value-free diagnostics. Observe new
diagnostics with `diagnosticSink`, or inspect `i18n.diagnostics`; neither includes translated text
or parameter values.

## Load remote catalogs atomically

`loadI18n` starts caller-provided sources and publishes a service only after all required results
validate. Networking, authentication, retry, cache, timeout, and abort ownership stay in the
application:

```ts
const controller = new AbortController();
const signal = AbortSignal.any([controller.signal, AbortSignal.timeout(5_000)]);

const i18n = await loadI18n({
  locale: 'nl',
  catalogs: [uiNl, formsNl, filesNl, datagridNl],
  signal,
  sources: [
    {
      name: 'application-catalog',
      async load({ signal: sourceSignal }) {
        const response = await fetch('/locales/nl.json', { signal: sourceSignal });
        if (!response.ok) throw new Error('Catalog request failed');
        return response.json();
      },
    },
  ],
});
```

An optional source can declare `required: false`; its failure is diagnosed while successful sources
still publish. The Node-only `jsonFileSource` follows the same source contract.

## Validate before publishing

Application overlays normally use partial validation: supplied messages must be valid, but they do
not need every framework key. Official framework catalogs use strict validation against English,
including key parity, placeholders, and co-visible accelerator scopes:

```ts
import { validateCatalog } from '@jsvision/i18n';

const issues = validateCatalog(candidate, {
  mode: 'strict',
  referenceCatalog: english,
  placeholderManifest,
  acceleratorManifest,
  official: true,
});
```

Runtime overrides are atomic. `i18n.setCatalog(nextCatalog)` validates the entire replacement before
publication; if validation throws, every reader continues to see the previous catalog.

## Localized Theme Designer recipe

The executable [Localized Theme Designer example](../examples/i18n-theme-designer.ts) demonstrates
explicit Dutch locale imports, application-last ordering, one service, and
`createApplication({ i18n })`. The Theme Designer itself remains application code: localization
does not introduce a global registry or force UI packages to bundle every language.

## Migration

For a no-config English application, no change is required. Introduce `createI18n` only when the
application needs another locale or application-owned messages, then inject it into
`createApplication`.

When migrating from BlendSDK, replace tuple-style plurals with `plural(parameter, cases)`, replace
implicit string coercion with named `params`, and move filesystem loading to `@jsvision/i18n/node`.
JSVision owns this implementation; `@blendsdk/i18n` is not a runtime dependency. Concepts and
behavioral tests adapted from the MIT-licensed package are attributed in the published
`THIRD_PARTY_NOTICES.md`.
